# Gouvernance du contenu

Chaque scénario, source, module, document ou checklist doit exposer un statut, une version et une date de revue. La publication d’un contenu critique relève d’une validation humaine compétente ; aucun workflow applicatif ne peut publier automatiquement un conseil réglementaire.

| Statut | Usage autorisé | Action attendue |
|---|---|---|
| `VERIFIED` | Orienter l’utilisateur dans le périmètre défini. | Revoir avant l’échéance indiquée ou lors d’un changement connu. |
| `NEEDS_REVIEW` | Préparer une vérification, jamais conclure seul. | Faire valider le contexte et les sources applicables. |
| `OUTDATED` | Conserver pour l’historique ou l’analyse d’écart. | Ne pas s’appuyer dessus pour une décision actuelle. |
| `DRAFT` | Travailler en édition. | Revue éditoriale et scientifique requise avant publication. |
| `ARCHIVED` | Consulter l’historique. | Ne pas présenter comme applicable par défaut. |

## Cycle éditorial

1. Une demande est créée via le backlog avec une description générale et non identifiante.
2. Un responsable attribue une source, une juridiction, un propriétaire et une cible de revue.
3. Le contenu est rédigé avec ses limites, ses acteurs et les incertitudes explicites.
4. Une revue compétente vérifie le périmètre, les sources et la formulation.
5. La version validée est publiée avec une date de prochaine revue ; l’ancienne version est conservée dans l’historique.

> Le tableau d’administration aide à préparer et à tracer cette gouvernance. Il n’équivaut pas à une preuve de conformité, une approbation éthique, une délégation ou une autorisation réglementaire.
